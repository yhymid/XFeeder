# XFeeder 2.2.0 — Final Big Tweaks Before 3.0

This release finishes the 2.x usability and reliability work before 3.0 development.

- Control XFeeder's network usage with bandwidth presets, separate Custom download/
  upload limits and opt-in Friendly Mode. Existing configs keep Unlimited by default.
- Manage network settings in the redesigned dashboard and see live worker status.
- Reduce browser resource requests with configurable Scrapling Resource Saving.
- Forward feeds to Telegram and Discord, with independent delivery state per destination.
- Challenge pages are rejected instead of becoming feed entries. Retry, timeout and
  shutdown behavior is covered by expanded regressions and real browser smoke tests.
- Use secret-redacted Expert diagnostics and configure an explicit public origin for
  dashboards behind HTTPS reverse proxies.

## Upgrade

For a fresh installation, download `XFeeder-2.2.0-runtime.tar.gz`, extract it,
run `npm install`, then `node .`. The included config starts empty; add your feeds
and destinations using `npm run dashboard` or edit `config.json` before forwarding.
Restart the worker after adding the first channel. When upgrading, preserve your
existing config instead of overwriting it with the empty starter.

Use Node.js **20.18.1+**, run `npm ci`, and retain your own `config.json`, `.env` and
cache. Run `node main.js --check-config` before restarting services. Browser fetching
requires Python 3.11+ and `npm run scrapling:install`; check it with
`npm run scrapling:check`. The optional virtualenv and Chromium are not bundled.
For HTTPS dashboard proxies, set `XFEEDER_DASHBOARD_PUBLIC_ORIGIN` and a dashboard
password in the service environment. See README for the exact setup.

## Limits

Application throttling is not router QoS and cannot guarantee lower ping. Browser
bandwidth/byte totals are not measured by the Node limiter. Upload pacing covers known
buffered bodies, not multipart/streamed bodies or redirect replay. Unlimited still has
measurable overhead in transport stress tests; measured results are documented.

The runtime download omits tests, developer documentation, changelog and release
notes, while retaining the MIT license. It contains no secrets, .venv, node_modules,
cache, logs or browser binaries. Full sources remain in the repository and GitHub's
source archives. No 3.0 refactor is included.

## Removed before 3.0

Legacy Matrix delivery and FreshRSS-specific integration/compatibility are removed
intentionally. Use Discord or Telegram destinations. Standard RSS/Atom URLs,
including those generated by FreshRSS, continue through the generic feed pipeline.
Unsupported configuration sections are reported, not executed; remove obsolete
sections and validate your configuration before starting the worker.
