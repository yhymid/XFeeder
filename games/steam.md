# Games on Steam

[← Index](../README.md)

Most PC games publish their patch notes as Steam announcements. Valve exposes them three ways. All three are free, need no API key, and were checked on **2026-11-23**.

## Sources, best first

| # | Source | URL template | Official? | What you get |
|---|---|---|---|---|
| 1 | Store events JSON | `https://store.steampowered.com/events/ajaxgetadjacentpartnerevents/?appid=<APPID>&count_before=0&count_after=10&lang_list=0` | Valve's own store backend, **undocumented** | `event_type` (patch / news / broadcast…), tags, full BBCode body, images, edit time, sometimes `build_id` |
| 2 | Store RSS | `https://store.steampowered.com/feeds/news/app/<APPID>/` | official (Steamworks docs) | always 10 items, full HTML body, capsule image only when the post has one |
| 3 | Web API GetNewsForApp | `https://api.steampowered.com/ISteamNews/GetNewsForApp/v2/?appid=<APPID>&count=10&feeds=steam_community_announcements&maxlength=0` | official, documented | BBCode body, tags; no `event_type`, no images |

- **Sources 1 and 2 share the same post id** (`gid`). The RSS link is `https://store.steampowered.com/news/app/<APPID>/view/<gid>`, so you can switch between them without reposting anything.
- Source 3 uses a different id, so dedupe it by title and date.
- **XFeeder reads source 1 since Beta 3da345e** (`src/steam_events.rs`): put the events URL in `RSS`. Entries get the category `Patch`, `Major update`, `Beta`, `Release` or `News` plus `event_type:N`; broadcasts and streams are dropped. Tested on all 195 games below on 2026-11-23.
- Without `feeds=steam_community_announcements`, source 3 also returns press articles (PC Gamer, PCGamesN…).
- Paging:
  - events: `ajaxgetpartnereventspageable/?appid=<APPID>&clan_accountid=0&offset=N&count=N`
  - GetNewsForApp: `&enddate=<unix>`
- Caching: events 300 s (answers `If-Modified-Since` with 304), RSS 120 s, GetNewsForApp `Expires` 1 h. Polling a game more often than every 5 minutes gains nothing.
- **Do not use** `steamcommunity.com/games/<appid>/rss/`. For games with a vanity name (CS2 = `CSGO`) it returns HTTP 200 with an HTML error page.

## Telling patches from news (`event_type`)

From Valve's `EProtoClanEventType`, checked against real posts:

| Type | Meaning | Use as |
|---|---|---|
| 12 | Small update / patch notes | **patch** |
| 13 | Regular update | **patch** |
| 14 | Major update | **patch** |
| 10 | Game release | patch (launch) |
| 29 | Beta release | patch (beta) |
| 30, 32, 33 | In-game content / season release / season update | patch |
| 28 | News | news, **unless the title looks like a patch** (PUBG and Project Zomboid post real patch notes as 28) |
| 34 | Crosspost | news (often a duplicate) |
| 35 | In-game event | news |
| 11 | Broadcast | **skip**: 47 of PUBG's last 100 posts |
| 17–19, 36 | Streams, creator home | skip |
| 9, 15, 16, 20–27, 31 | Chat, DLC release, future release, sales, in-game bonuses / loot / perks / challenges / contests, IRL event, free trial | news. Seen in real feeds on 2026-11-23: 9 (Hell Let Loose: Vietnam), 15 (ETS2, PAYDAY 3), 20 and 23 (EVE Online), 21–22 and 31 (PAYDAY 3), 26 (skate), 27 (Dark and Darker). Drop them with an Exclude on `event_type:N` if they are noise. |

- The `patchnotes` tag appears only on type 12. Filtering by that tag alone misses big updates such as Deadlock's Halloween update (type 13) and Dota 7.42 (type 14).
- Title regex that catches the type-28 patches:
  `(?i)\b(patch(\s*notes)?|hotfix|update\s*v?\d|v?\d+\.\d+(\.\d+)?\b.*(released|stable|unstable)|release notes|changelog)\b`

## SteamDB links

[SteamDB](https://steamdb.info) is a community site, not Valve. Its pages are good for people to click, but the site forbids scraping (see [Build and branch changes](#build-and-branch-changes-what-steamdbs-history-tab-shows)). The URL templates below come from a real SteamDB page saved on 2026-11-23. Each game row further down links its SteamDB patch notes page and RSS.

| What | URL template | Example (CS2) |
|---|---|---|
| Patch notes list of a game | `https://steamdb.info/app/<APPID>/patchnotes/` | [730](https://steamdb.info/app/730/patchnotes/) |
| Patch notes RSS | `https://steamdb.info/api/PatchnotesRSS/?appid=<APPID>` | [730](https://steamdb.info/api/PatchnotesRSS/?appid=730) |

- `<BUILDID>` and `<CHANGENUMBER>` are the same numbers that anonymous SteamCMD prints (`buildid`, `change number`), so a bot that reads Steam itself can still give people SteamDB links.
- The patch notes RSS is `Disallow`ed in robots.txt and "not intended to be used for automatically monitoring". It works, but poll it at most once an hour (its `ttl` is 3600).

## Build and branch changes (what SteamDB's History tab shows)

SteamDB's `https://steamdb.info/app/<APPID>/history/` shows, per changelist, `public` branch `buildid` changes (old › new), added or removed branches (betas, version pins such as CS2 `1.42.0.0`), depot size deltas, and noise (`review_percentage`, community items, timeline markers). Checked on 2026-11-23:

- **SteamDB forbids scraping it.** The FAQ says "We also do not allow scraping/crawling on SteamDB … get the information from Steam itself" and warns about automatic bans. The page answers **403** to a non-browser client from home and from the XFeeder VPS.
- **`/api/PatchnotesRSS/` is `Disallow`ed in robots.txt**, and the FAQ says the RSS "is heavily cached and is not intended to be used for automatically monitoring for new patches". It still answers 200 (with `ttl` 3600) from home and the VPS. Prod polls it every 30 minutes for 8 apps.
- **The same data comes from Steam itself (PICS)**, as the SteamDB FAQ suggests. Anonymous SteamCMD returns it without an account:
  `steamcmd +login anonymous +app_info_update 1 +app_info_print <APPID> [+app_info_print <APPID> …] +quit`
  - `depots.branches.<name>` gives `buildid`, `description`, `timeupdated` and `timebuildupdated`. For CS2 on 2026-11-23, `public` = 26798866, the same as SteamDB's newest PatchnotesRSS item. `1.42.0.0` and the other version pins are listed with their descriptions.
  - `depots.<id>.manifests.public` gives `gid`, `size` and `download` per depot (the size deltas on the History tab).
  - `privatebranches` = 1 means that password branches exist; they are not listed.
  - Cost: one run for 8 apps took **8 s** on the VPS once SteamCMD had updated itself. The first run of the day downloads a 41 MB self-update (24 s).
  - `/usr/games/steamcmd` is already installed on the XFeeder VPS.
  - Each app's header line carries the PICS changelist: `AppID : 570, change number : 41321468/41321468, last change : …`. That is the same `#…` number as on SteamDB's History tab, so an unchanged number means nothing changed for that app.
  - **Works for any public AppID.** On 2026-11-23 it returned `public` buildids for Dota 2 (570), Apex Legends (1172470), Marvel Rivals (2767030), Baldur's Gate 3 (1086940, plus 2 old patch branches), HELLDIVERS 2 (553850), ELDEN RING (1245620) and Stardew Valley (413150, plus `legacy_1.5.6`, `legacy_1.6.8`, `compatibility` and `previous_version`). Most games expose only `public`. Version-pin branches like CS2's are a Valve habit.
  - **A wrong or unknown AppID is not an error.** For `999999999` SteamCMD exits with 0 and prints `change number : <current global number>`, `last change : Thu Jan  1 00:00:00 1970` and an empty `{ }`. Treat "no `depots.branches.public`" as no data, never as "branch removed".
  - The output contains ANSI colour codes (`ESC[0m`), sometimes at the start of the `AppID :` line. Strip them before parsing.
  - The CS2 change number from SteamCMD (41339555) was the newest changelist on SteamDB's History tab, so the two agree.
  - A second check on 2026-11-23 with all 10 tracked apps plus one bogus AppID took **9.3 s**.
- **Real CS2 History-tab data** (1835 changelists, 2023-03-18 → 2026-11-21, saved from a browser by the user):
  - `public` gets a new buildid about **110 times a year** (2 a week). Each time `buildid`, `timeupdated` and the depot `gid`/`size`/`download` change together, and the page shows the size delta (`+2.1 GiB`).
  - Version branches (`1.41.x`, `1.42.0.0`): in 2026, 42 were added, 42 removed and 39 changed. A new one usually appears together with the public update and replaces the previous pin.
  - Noise: `dpr`/`dprp` (internal, about 430 changes in 2023–2024, almost none since 2025), Timeline Markers Update (481), `review_percentage`, user tags, assets, trailers, screenshots.
  - Rare but readable: Steam Deck / Steam Frame compatibility, supported languages, `ListOfDLC`, `MinClientVersion`.
- What to track: a `public` buildid change = new build (link `https://steamdb.info/patchnotes/<buildid>/` for humans, `https://store.steampowered.com/news/app/<APPID>` for the official notes); a branch that appears or disappears = new beta / version pin; a non-public buildid change = beta update. Ignore everything else. Dedupe by `<appid>:<branch>:<buildid>`.

## Images

- **App art guesses:** `store_item_assets/steam/apps/<APPID>/header.jpg` is missing (404) for 22 of 202 apps checked on 2026-11-23, because newer apps keep it under a hashed path (`…/<APPID>/<hash>/header.jpg`, given by `api/appdetails` as `header_image`). `library_hero.jpg` exists for 194 of 202; 7 apps have neither. XFeeder (Beta 5a8fddc) checks header → library hero → no image.
- All 1778 capsule and body images of the last 10 posts of 202 apps loaded (200, `image/*`). `{STEAM_CLAN_LOC_IMAGE}` is a second placeholder for the same clan CDN.

| What | URL |
|---|---|
| Post capsule / title image | `https://clan.fastly.steamstatic.com/images/<clanid>/<file>`, where `clanid` is `announcement_body.clanid` and the file comes from `jsondata.localized_capsule_image[0]` |
| Images inside the body | replace `{STEAM_CLAN_IMAGE}` / `{STEAM_CLAN_LOC_IMAGE}` with `https://clan.fastly.steamstatic.com/images` |
| Current game header | `https://store.steampowered.com/api/appdetails?appids=<APPID>&filters=basic` → `header_image` |
| Legacy header (may be old art) | `https://shared.fastly.steamstatic.com/store_item_assets/steam/apps/<APPID>/header.jpg` |
